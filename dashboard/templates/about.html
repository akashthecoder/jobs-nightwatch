The problem

Job boards are built to show you what exists right now. Nobody tells you what changed.

A role you have been tracking for three weeks quietly adds a requirement you do not have. A posting gets rewritten from “Data Scientist” to “Principal Data Scientist” and the experience bar moves from five years to twelve. The job you applied to last Tuesday is pulled on Thursday and nobody says a word.

You would only notice any of this by re-reading every posting you care about, every day, and remembering exactly what each one used to say. Nobody does that. That gap is what this system fills.

How it works

Jobs NightWatch watches {{ stats.companies }} companies’ career pages on a timer. It remembers every posting it has seen. When something changes, it reads the posting properly, works out whether the change matters to you, and writes up what you would say if you applied.

1. It runs itself

Cloud Scheduler wakes the system every few hours. This is the difference between an agent and a website you have to remember to visit. You can also trigger a run yourself with the Run now button.

2. It remembers

Every posting is normalised and fingerprinted with a SHA-256 hash of its content. Today’s fingerprint is compared against the one stored last time. That comparison is plain deterministic code — no AI. Deciding whether two records differ is a comparison, not a judgement; using a language model there would be slower, more expensive, and less accurate than a hash.

A company’s first run reports nothing, on purpose. “Changed” is undefined when there is no previous version to compare against. Treating everything you see for the first time as “new” would fire {{ stats.postings }} alerts nobody wants. The first collection quietly establishes a baseline; alerting starts from the second run.

3. It filters before it thinks

Of {{ stats.postings }} postings being watched, {{ stats.matches }} match your profile — a deterministic check against your target titles and core skills. This is a cost guard, not the fit decision. A warehouse role does not need a language model to rule it out.

4. Then the agent reasons

Only changes that survive the filter reach Gemini 3.7 Flash. The agent decides which tools to call: it fetches your profile, retrieves what the posting said last time, runs a deterministic eligibility check, and records its verdict. The model does all the judging; the tools only fetch facts and save results.

5. And it tells you honestly

  • Most changes are not worth your attention, and it says so. A long list of weak matches is worse than three real ones.
  • Application bullets cite real specifics from your background — named systems and actual numbers, not “strong analytical skills”.
  • Concerns are surfaced, not buried. A seniority gap, a missing skill, or an unstated visa position all get flagged.
  • Silence is reported as silence. If a posting says nothing about sponsorship, the agent says “not stated” rather than guessing in either direction.

What it does not do

It is not a job board. The company view shows which roles match your profile, but the model is only ever spent on roles that changed. Scoring all {{ stats.matches }} matching roles would cost hundreds of model calls to tell you nothing you did not already know.

It is single-tenant today. One profile, one set of tracked companies. The data model was built to allow per-user profiles later, but that is not built yet.

Built with

  • Gemini 3.7 Flash on Vertex AI — the reasoning
  • Google Agent Development Kit (ADK) — the agent loop and tool calling
  • Cloud Run — three services: collector, agent, dashboard
  • Pub/Sub — one message per change, so a slow or failing posting cannot block the others
  • Firestore — postings, history, decisions and profile
  • Cloud Scheduler — the timer that makes it autonomous
  • Greenhouse job board API — the data source
